Project Overview

This project was developed as part of the COMP1640 — Enterprise Web Software Development group coursework. The specifications required students to work in teams of 7-8 members, taking part in various roles of enterprise development. This Kingsford University Magazine Contribution Management System was developed as the prodcut of the coursework.

Team InnovateX was tasked to create a university contribution submission portal that handles annual magazine submissions from its large population of students. The existing magazine submission process relied entirely on email communication, creating inefficiencies for all stakeholders. Submissions were frequently misplaced in inboxes without acknowledgement or receipt; lacking a centralised view of the selection process across all nine faculties. The main objective of the project was to replace this process with a secure, role-based enterprise web platform.

Development Process

The team followed Agile SCRUM methodology across four sprints in the span of 9 weeks. A total of 22 stand-up meetings were held over 70 days, accumulating 1,050 minutes of recorded meeting time. Additionally, three customer review meetings were held at the end of each development sprint to gather feedback and confirm requirement coverage.

System Architecture

The application is built on Laravel due to its enterprise-compatibility. Blade's templating inheritance and component system is used throughout, with role-aware rendering via @if(auth()->user()->hasRole()) allowing one page to display different UI elements for each of the five user roles without duplicating views.

The database is MySQL, accessed through Laravel's Eloquent ORM. The schema is centred on a Users table with one-to-zero-or-one relationships to separate Students and Staff tables. Contributions is the other key entity, linking to Contribution_files, Comments, Academic_Years, and Faculties. The Reports and Notifications tables use polymorphic relationships (reportable_type, notifiable_type) to remain extensible without additional pivot tables. Notification IDs use UUID stored as CHAR(36) to prevent enumeration attacks.

Role-based access control is managed via Spatie Laravel Permissions, storing roles and permissions in the database rather than hard-coded logic. This means new roles or permission adjustments can be made without modifying application code. Files (Word documents, PDFs, images) are stored in Cloudflare R2 (an S3-compatible object store), with each file renamed to a UUID on upload to prevent path traversal attacks and name collisions. Emails are dispatched through Brevo with Cloudflare Email Routing forwarding inbound messages to role-based addresses at the ksf.it.com domain.

Key Features & Implementation

Contribution Submission — When a student submits a contribution, all three operations (creating the contribution record, uploading files to Cloudflare R2, and emailing the coordinator) are wrapped in a DB::transaction() to guarantee data integrity. A rollback occurs if any step fails, preventing orphaned records or missing files.

Deadline Enforcement — Each academic year has two closure dates set by the Administrator. The first prevents new submissions but allows edits; the final closure date locks all updates system-wide. Automated reminder emails are sent to coordinators for submissions that have gone uncommented beyond 14 days.

ZIP Download — After the final closure date, the Marketing Manager can download all approved contributions as a single ZIP file. Files are retrieved from Cloudflare R2 and assembled into a temporary archive using addFromString(), which is then streamed as a download response and immediately cleaned up with deleteFileAfterSend(true).

Analytics Dashboard — The administrator dashboard provides contribution statistics per faculty (total, approved, rejected), filterable by academic year, rendered with Charts.js. User activity is measured by submitted contributions for students and by comment and approval counts for coordinators. Exception reports surface contributions with no comments and those overdue past 14 days.

Performance Optimisation — Slow contribution page load times were resolved by adding database indexes on student_id, post_id, academic_year_id, status, and is_selected columns, reducing query complexity from O(n) to O(log n). Eager-loading comments was replaced with a withCount('comments') COUNT subquery, cutting contribution data load times by approximately 40%. Mobile page performance was improved by serving compressed WebP hero images via media queries, reducing Largest Contentful Paint from 17.5 seconds to 2.8 seconds.

Additional Features — Last login date, time, and browser type are recorded at every login via an UpdateLoginInfo event listener and displayed on user profiles and the admin panel. Soft delete is implemented across all major modules, allowing administrators to restore records. Magazine posts track view counts via Laravel's increment() method. Guest accounts can self-register with a personal email, selecting a faculty to view its selected contributions and statistics; the faculty coordinator is notified by email and in-app notification when a guest registers.

Outcomes & Reflection

The Kingsford University Magazine Contribution Management System was successfully developed by Team InnovateX using Agile SCRUM methodology across three development sprints over nine weeks. All planned tasks were completed by their respective team members, and the customer confirmed that all stated requirements were met at the final review meeting on 5 April 2026. The deployed system is live at ksf.it.com.

The project reinforced the value of Agile practices — 22 structured meetings and three customer review checkpoints kept the team aligned and allowed scope adjustments before they became costly. Working on an eight-person team with clearly defined roles (Product Owner, SCRUM Master, UI/UX, Database, Frontend, Backend, two Testers) made it possible to develop authentication, content management, analytics, and publication features in parallel across sprints.
